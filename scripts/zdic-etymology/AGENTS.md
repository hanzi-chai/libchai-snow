# 汉典字源采集

在仓库根目录运行，需要 Node.js 22.18+，依赖安装在根目录：

```bash
npm ci
node scripts/zdic-etymology/fetch.ts
```

默认按 GB2312 区位顺序抓取全部 **6763 个汉字**（一级 3755、二级 3008），不包含符号和 GBK 扩展字。无需外部字表。

先试抓几个字：

```bash
node scripts/zdic-etymology/fetch.ts --chars 颖明一
node scripts/zdic-etymology/fetch.ts --limit 10
```

输出默认位于 `output/zdic-etymology/`：

- `etymology.json`：本次选定字集的成功记录数组，每字分别含 `字形分析`、`详细解释`、`说文解字`。
- `characters/u-<码点>.json`：逐字结果（小写十六进制码点，如颖为 `u-9896.json`），每字完成后立即原子写入，便于中断恢复。
- `html/u-<码点>.html`：完整网页缓存，可重新解析及人工核对。
- `status.json`：请求数、成功数、失败原因、未处理字及各字缺失的区域。

`字形分析` 是页首分析文本；另两项保存对应区域的**全文**、HTML 片段、图片地址和链接，包括多音字的全部解释、《说文解字》正文、繁体/异体字头转引说明及《说文解字注》。不按“形声”“会意”等关键词筛选，以免漏掉其他措辞的字源；因此普通释义、引文也会保留。图片只保存地址和 HTML 引用，不下载图像。站点在当前页面内展示的繁体转引内容会直接保存，链接也可追溯；不额外递归抓取异体字页面。

某区域在页面中不存在时记为 `null`，不推断其内容。遇到验证页或不匹配的字头会报错，不会当作“无字源”成功保存。站点结构变化也可能需要更新解析器；应结合 `status.json` 和缓存抽查结果。

重复运行会读取 HTML 缓存、重新解析，失败或未请求的字会重新下载。局部试跑只重建本次选定字集的汇总，不删除其他逐字文件或缓存；再次运行默认全量命令可重建全部汇总。

```bash
# 指定目录或更慢的请求间隔（单位毫秒，至少 1000）
node scripts/zdic-etymology/fetch.ts --out output/zdic-etymology --delay 3000
# 忽略已有缓存，重新下载所选字
node scripts/zdic-etymology/fetch.ts --chars 颖 --refresh
# 只解析缓存，不发送任何网络请求；缺少缓存记为失败
node scripts/zdic-etymology/fetch.ts --offline
# 全量离线解析，不发送网络请求
node scripts/zdic-etymology/fetch.ts --offline
```

网络请求串行执行，默认至少间隔 2 秒，全量初次运行至少约 3 小时 46 分钟，实际还需计入响应与重试耗时。每次请求超时 30 秒，默认最多重试 3 次并指数退避，429/503 响应遵循 `Retry-After`（未提供时至少等待 60 秒）；403 或连续五字失败停止整轮。Ctrl+C 会在当前操作结束后保存汇总，未完成时退出码为 1，重跑即可续爬。源码与依赖之外的采集产物都位于被忽略的 `output/` 内。
